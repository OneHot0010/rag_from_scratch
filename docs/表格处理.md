# 工业级 RAG 中 Excel / CSV 处理指南

> 面向企业级落地,系统梳理表格类文件(Excel / CSV)在 RAG 数据接入中的
> **踩坑点、优化点与需要考虑的问题**。适用于把结构化/半结构化表格纳入
> 检索增强问答的场景。

---

## 0. 一句话结论

表格 RAG 最该警惕两件事:
1. **解析阶段的"静默错误"**——合并单元格、表头错位、类型失真,程序不报错但数据已经错了;
2. **表格数据天然不适合纯向量检索做聚合/精确查询**——"求和、排序、Top-N、同比"这类问题,需要 Text-to-SQL / 代码执行 / 混合检索来补齐,而不是硬塞进向量库。

---

## 1. 解析正确性(最高优先级:错了也不报错)

| 问题 | 现象 / 原因 | 后果 | 应对 |
|---|---|---|---|
| **合并单元格** | openpyxl 只在合并区左上角返回值,其余格为 `None` | 分类列/表头大面积丢值 | 读取 `ws.merged_cells` 回填合并区域 |
| **表头不在首行** | 报表常有标题行、空行、备注行 | "首行即表头"直接错位 | 可配置 `header_row` / `skip_rows` |
| **多级 / 合并表头** | 两三行才构成完整列名 | 列语义丢失 | 多行表头按列纵向合并(如 `销售-Q1`) |
| **公式单元格** | `data_only=True` 依赖 Excel 缓存值;未被 Excel 打开计算过则为 `None` | 数值列整列为空 | 明确文档约束;必要时用 LibreOffice 预计算 |
| **类型失真** | 日期变序列号、大数变科学计数法、`0.1+0.2` 浮点噪声、工号 `007` 前导零丢失 | 数值/编号型内容失真 | 统一类型规范化(日期→ISO、数字去 `.0`、编号按文本) |
| **隐藏行列 / 筛选** | 隐藏的往往是脏数据或中间计算 | 噪声进库 | 按需跳过隐藏行列 |
| **.xls / 加密 / 损坏** | openpyxl 不支持旧版 .xls;加密文件直接报错 | 崩溃或静默失败 | 明确报错并给出转换建议;必要时接 xlrd |
| **CSV 编码** | UTF-8 / GBK / GB18030 / 带 BOM 混杂 | 中文乱码 | BOM 优先 + 候选编码探测 |
| **CSV 方言** | 分隔符 `, ; \t \|`、引号转义、字段内嵌换行 | 列被错切 | `csv.Sniffer` 嗅探分隔符;用标准库 `csv` 正确处理引号 |
| **空行 / 空表** | 报表尾部空行、空 sheet | 产生空 Document | 空行/空表跳过 |

---

## 2. Chunking 策略(表格与纯文本本质不同)

- **行级 chunk 是主流**:每行拼成 `列名: 值；...` 的自然语言文本,让 embedding 理解语义,并保留行号溯源。
- **表头语义要保留**:脱离表头的裸值(如 `上海`、`10`)几乎没有检索价值,必须 `列名: 值` 绑定。
- **宽表问题**:几十列的宽表单行会超长、稀释检索信号。应对:字段截断、只保留关键列、或按列分组拆分。
- **跨行语义**:透视表、分组小计、"合计行"无法用"一行一 chunk"表达,需要专门识别或在预处理阶段展开。
- **锚点注入**:把 `sheet 名 / 表名` 前置到 chunk,缓解多 sheet、多表同名列(如多个"金额")的歧义。

---

## 3. 检索与问答适配性(表格 RAG 的根本局限)

| 问题类型 | 纯向量检索 | 推荐方案 |
|---|---|---|
| 语义/描述类("哪些产品支持退货") | ✅ 适合 | 向量检索 |
| 精确匹配(SKU、身份证、编号) | ❌ 稠密向量不擅长 | BM25 / 关键词 / 元数据过滤 |
| 聚合计算(求和、平均、Top-N、同比) | ❌ 根本答不准 | **Text-to-SQL / pandas 代码执行** |
| 多条件过滤("华东区 Q1 金额>100") | ❌ | 结构化查询 / 元数据过滤 |

**核心建议**:表格问答应做**路由分流**——语义问题走向量检索;计算/精确/过滤问题把表加载为 DataFrame / 临时表,走 Text-to-SQL 或代码执行。二者结合(hybrid)才是企业级形态。

---

## 4. 规模与性能

- **大文件内存**:用 openpyxl `read_only` 流式读;百万行级避免一次性全量载入(注:需合并单元格信息时 read_only 不可用,需权衡)。
- **Embedding 吞吐**:不要逐条串行调用。工业级要 **批量(batch)+ 并发 + 限流重试(429/超时退避)**。
- **向量写入**:分批 upsert,边算边写,避免峰值内存。
- **增量更新**:表格数据会变。按 **文件指纹 + 行主键** 做增量索引与去重,而非每次全量重建。

---

## 5. 数据治理与合规(企业级必备)

- **PII / 敏感信息**:表格常含手机号、身份证、薪资、客户名单。入库前做 **PII 识别与脱敏**。
- **权限控制**:行级 / 列级 ACL,不同用户可见范围不同;检索结果需按权限过滤。
- **可溯源**:metadata 至少含 `source / sheet / row`,进阶含 **版本、更新时间、数据 owner**,回答时能指明"出自哪张表哪一行"。
- **审计**:谁在何时用哪份数据回答了什么,可审计、可回溯。

---

## 6. 工程健壮性

- **逐文件 / 逐 sheet 隔离容错**:一个文件或 sheet 解析失败不阻断整批。
- **结构化日志**:记录跳过的行数、空值率、编码/分隔符探测结果。
- **解析质量报告**:产出"共 N 行、跳过 M 行、K 列空值率过高"的体检报告,便于发现脏数据。
- **持久化向量库**:内存数组仅适合 Demo,生产用 Chroma / Milvus / Qdrant / pgvector。

## 7. 优化清单(按优先级)

### P0 · 正确性(不做会静默给错答案)
- [x] 合并单元格回填
- [x] 可配置表头(起始行 + 多级表头合并)
- [x] 类型规范化(日期→ISO、数字去 `.0`、编号保留前导零、浮点噪声抑制)
- [x] CSV 编码嗅探(BOM + GBK/UTF-8 候选)
- [x] CSV 方言嗅探(分隔符/引号)
- [x] 空行 / 空表跳过、sheet 锚点注入

### P1 · 检索质量
- [ ] 混合检索(向量 + BM25)+ 元数据过滤
- [ ] chunk 前置表名/表头描述作为锚点(已部分实现:sheet 锚点)
- [ ] 聚合/计算类问题走 Text-to-SQL / 代码执行分支

### P2 · 规模与性能
- [ ] 批量 + 并发 embedding,带限流重试
- [ ] 增量索引(文件 hash + 行主键去重)
- [ ] 大表分片流式处理

### P3 · 治理与工程
- [ ] 入库前 PII 检测与脱敏;行/列级 ACL
- [ ] 完整 metadata(版本/时间/owner)+ 审计日志
- [ ] 逐文件容错 + 解析质量报告 + 结构化日志
- [ ] 持久化向量库

## 8. 本项目已落地(阶段 2.1)

在 `ragcore/loaders/` 中,P0 正确性优化已实现:
- `excel_loader.py`:合并单元格回填、可配置表头、多级表头、逐 sheet 容错、sheet 锚点;
- `csv_loader.py`:编码嗅探、方言嗅探、可配置跳过行;
- `_tabular.py`:Excel/CSV 共享的类型规范化、表头清洗、行转文本、空行判定。

P1–P3 作为后续阶段迭代方向。
